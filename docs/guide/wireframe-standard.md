와이어프레임을 같은 기준으로 그리기 위한 약속입니다. 색·글꼴·모서리는 디자이너의 파운데이션이 나오면 그 값으로 바꾸고, 여기서는 **크기·배치·상태·번호**만 정합니다. 화면마다의 레이아웃은 흔한 레퍼런스 사례를 참고한 것으로 확정이 아니며, 디자인에서 새로 정해도 됩니다(4차 회의).

## 1. 화면 크기

- **기준 화면은 1920×1080 데스크톱 웹**입니다. 모든 와이어프레임은 이 크기의 틀 안에 그립니다.
- 1사이클은 데스크톱 웹만 다룹니다. 1280보다 좁은 화면과 모바일 웹은 [미결정]입니다.
- 설계서 보드에서는 1920×1080 틀을 줄여서 넣고, 외곽선이 잘리지 않게 틀 둘레에 여백을 둡니다.

## 2. 화면 틀

![화면 틀 1920×1080](/design/std-frames.png)

| 틀 | 쓰는 화면 | 크기 |
| --- | --- | --- |
| A-1 상단 내비게이션 (투표 시안) | 홈, 자료 넣기, 회차 구분, 설정 | 상단 바 높이 64 · 콘텐츠 폭 1200 · 좌우 여백 360 |
| A-2 왼쪽 사이드바 (투표 시안) | A-1과 같음 | 사이드바 폭 240 · 남은 1680 안에 콘텐츠 폭 1200 |
| A-3 집중 모드 | 필사, 퀴즈 | 전용 바 높이 64(뒤로·회차·단계·진행) · 콘텐츠 폭 960 · 좌우 여백 480 |

- 내비게이션 형태(상단 / 사이드바)는 [세부 경험 결정 원칙](../product/principles)의 "페이지 구성·내비게이션" 항목으로, 시안·투표로 정합니다(4차 회의에서 정하지 않음). 정해지기 전까지 와이어프레임은 **A-1 상단 내비게이션**으로 그리고, 콘텐츠 영역(폭 1200)은 두 시안이 같으므로 그대로 씁니다.
- 필사·퀴즈는 내비게이션 투표와 상관없이 A-3 집중 모드입니다.

## 3. 그리드·간격

- **12단 그리드, 단 사이 24px**. 콘텐츠 폭 1200이면 한 단은 78px, 960이면 58px입니다.
- **간격은 4의 배수**만 씁니다: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96.
  - 요소 안: 8–16 / 요소 사이: 16–24 / 묶음 사이: 32–48 / 페이지 제목 아래: 48

## 5. 공통 부품

![공통 부품](/design/std-comps.png)

- **버튼**: L 48 · M 40 · S 32. 주 버튼(채움) / 보조 버튼(테두리) / 텍스트 버튼. 한 화면에 주 버튼은 하나입니다.
- **상태 이름**은 이 단어만 씁니다: default · hover · pressed · focus · selected · disabled · loading · error · empty.
- **입력 칸** 높이 48. 오류 문구는 원인이 된 칸 바로 아래에 둡니다.
- **토스트**는 화면 아래 가운데, 3초 뒤 사라집니다. **모달**은 되돌릴 수 없는 동작(다시 나누기, 기록 삭제) 전에만 씁니다.
- **빈 화면**에는 다음 행동 버튼 하나를 둡니다. **불러오는 중**이 1초를 넘으면 회색 막대(목록 자리) 또는 스피너를 보여 줍니다.
- 색은 무채색 6단계만 씁니다. 메인 컬러·오류 색(빨강)은 넣지 않고, 실제 화면에서 색이 필요한 곳은 설명에 적습니다(예: 틀린 글자는 빨간색, TRN-07).

## 6. 화면 번호

화면 번호는 `대분류.화면.변형` 입니다. [전체 흐름·화면 목록](../product/flow)과 같은 번호를 씁니다.

| 대분류 | 이름 | 화면 |
| --- | --- | --- |
| 0 | 진입·계정 | 0.1 시작 화면 · 0.2 샘플 체험 · 0.3 로그인 · 0.4 회원가입 · 0.5 설정 |
| 1 | 홈 | 1.1 내 자료 |
| 2 | 자료 넣기 | 2.1 자료 넣기 · 2.2 파일 선택됨·오류 |
| 3 | 회차 구분 | 3.1 나누는 중 · 3.2 회차 확인·조정 · 3.3 나누기 실패 |
| 4 | 필사 | 4.1 회차 목록·진행 · 4.2 따라 쓰기 · 4.3 빈칸 · 4.4 백지 · 4.5 백지 비교 · 4.6 단계 완료 |
| 5 | 퀴즈 | 5.1 퀴즈 풀기 · 5.2 퀴즈 결과 |

- 세 번째 자리는 같은 화면의 탭·상태·시안입니다. 예: 2.1.1 파일 올리기 탭, 2.1.2 텍스트 붙여넣기 탭, 3.2.A 조정 시안 A.
- 기존 화면 ID(SCR-UPL-01 등)는 정책서와 연결하려고 함께 적습니다.

## 7. 화면 설계서 보드

- 위쪽에 화면 번호와 제목(예: 2.1.1 자료 넣기 · 파일 올리기), 왼쪽 회색 캔버스에 1920×1080 화면, 오른쪽 패널에 번호별 설명을 둡니다.
- 오른쪽 설명은 `번호 요소명 컴포넌트 종류`(예: ⑥ 회차 나누기 Button)로 시작하고, 아래 순서로 씁니다.
  1. 무엇인지, 진입할 때 어떤 상태인지 ("진입 시 disabled 상태입니다.")
  2. 동작 ("클릭할 경우 3.1 회차 나누는 중 화면으로 이동합니다.")
  3. 상태 목록 ("상태: default, hover, pressed, disabled, loading")
  4. 예외·문구가 있으면 그 문구를 따옴표로
- 레퍼런스 화면에는 빨간 번호를 그리고, 오른쪽 설명의 ①②③과 맞춥니다.
- 번호는 화면 밖(요소 왼쪽·오른쪽·위)에 붙이고, 번호를 넣으려고 화면 배치를 바꾸지 않습니다.

## 8. 화면 문구

화면에는 필요한 말만 둡니다. 기능 설명은 설계서(번호 설명)에 쓰고 화면에는 쓰지 않습니다.

- **보기 전에는 모르는 사용법만 한 줄로 알립니다.** 예: "파일을 여기로 끌어다 놓거나", "끌어서 순서를 바꿀 수 있어요", 단축키 안내. 버튼만 봐도 아는 동작은 쓰지 않습니다.
- **처음 한 번만 필요한 안내는 말풍선으로** 띄우고 다시 보여 주지 않습니다.
- **오류는 제목 + 해결 한 줄**입니다. 제목은 무엇을 못 했는지, 본문은 어떻게 하면 되는지. 예: "스캔한 PDF는 아직 올릴 수 없어요 / 글자로 된 PDF를 올려 주세요."
- **진행 중은 "~하는 중"**, 끝나면 짧은 과거형("저장됨", "삭제했어요")으로 씁니다. 오래 걸리면 걸리는 시간이나 떠나도 되는지를 함께 적습니다.
- **빈 화면은 제목 한 줄 + 무엇을 하면 채워지는지 한 줄 + 버튼 하나**입니다.
- **규칙이 앞 단계와 달라질 때만** 알립니다. 예: 백지 단계 "백지는 오타가 있어도 넘어가요".
- 참고: 매니패스트(manyfast.io) 화면 문구 — "기능을 고르면 상세가 열려요", "위임을 추가할 수 없어요 / 이미 위임 중인 기간과 겹쳐요", "자료 2개를 읽는 중".
